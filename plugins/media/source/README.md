# Now Playing (com.clarkyau.nowplaying) – source

Plugin for the Ajazz AKP153E and the Ajazz / Mirabox **Stream Dock** software.
Actions: Album Art, Track Info, Time, Progress Bar and six media buttons.
Neighbouring Album Art / Progress Bar keys share one graphic; Track Info keys
side by side form a strip where long names scroll across the keys (the one
place text may cross keys, at the owner's request). Track info comes from Windows'
own media controls (`media.ps1`, built-in PowerShell), so it works with
Spotify, browsers, Apple Music, etc. with no sign-in.

End users only need the build zip (extract, run `install.bat`).

## Layout

```
src/
  index.js     talks to the Stream Dock software, keys, settings, scrolling clock, drawing loop
  layout.js    joining: shared album art / progress bar, Track Info groups and strips, Automatic
  render.js    SVG for every key type (text kept inside one key, line-icon buttons)
  raster.js    resvg (WebAssembly) + bundled Barlow Semi Condensed font -> 144x144 PNG
  media.js     runs media.ps1, keeps track/timeline/art, picks the album colour
  settings.js  per-key settings, defaults, conversion from the old dev.nowplaying.deck plugin
  migrate.js   moves old keys to this plugin inside a profile (used by tools and tests)
plugin/com.clarkyau.nowplaying.sdPlugin/
  manifest.json, en.json        generated by tools/make-manifest.js
  plugin/media.ps1              Windows helper (track, position, artwork, commands)
  plugin/assets/                resvg.wasm, fonts (OFL) and licences
  plugin/index.js               <- built by "npm run build"
  propertyInspector/index.html  settings panel (only shows options for the key type)
  static/                       action icons, generated by tools/make-icons.js
installer/     install.bat, uninstall.bat, install.ps1 (also migrates dev.nowplaying.deck keys)
tools/         make-manifest.js, make-icons.js, migrate-profile.js
test/          fake Stream Dock host, fake media player, tests, previews (test/out)
```

## Build and test

```
npm install
npm run build        # bundle src/ -> plugin/.../plugin/index.js
npm test             # build + deck tests on Node 20.8.1 + previews in test/out
npm run package      # build + test + dist/NowPlaying-build.zip and NowPlaying-source.zip
```

Extra tests:

- `python test/panel-test.py` – settings panel in headless Chromium (pip: playwright, websockets).
- `PWSH=pwsh node test/installer-test.js` – runs `install.ps1` against a copy of
  a real profile with old keys and checks it matches `src/migrate.js`.

`npm test` runs the plugin on Node 20.8.1 (the `node-linux-x64` dev dependency,
or set `NODE20=` to a Node 20 binary) against `test/mock-host.js`, which reports
key positions the way the AKP153E does. Every image is checked automatically:
144x144 PNG (or SVG without `#`, `%` or tspan edge spaces), no text under 19 px,
text never running off its key (only Track Info strips may scroll across keys),
time numbers at least 38 px.

## Things learned the hard way

- Key positions arrive in hardware order: `index = row*5 + column`, real column
  `4 - floor(index/3)`, real row `index % 3`. The side screen (column 5) is normal.
- All key images are drawn here with resvg and sent as PNG, so the software's
  SVG quirks (`#`, `%`, stripped tspan spaces) never apply, and text can be
  measured exactly with the bundled font.
- Album art and progress bars spanning keys treat 28 px (≈0.2 of a key) between
  keys as hidden so the picture lines up across the gaps.
- WinRT objects from awaited calls are untyped in PowerShell; `media.ps1` calls
  .NET through reflection. Players report position only now and then, so the
  plugin counts on from the reported time while playing.
- Profiles are plain UTF-8 JSON (no byte-order mark); migrations must keep that
  and must run while the software is closed (it rewrites profiles on exit).
